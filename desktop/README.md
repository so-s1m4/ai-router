# AI Router для macOS

Приложение открывает существующий сайт целиком: чаты, проекты, настройки и вход в тот же аккаунт. В приложение входит небольшой мост файлов и терминала. Модели и агент работают на серверном исполнителе; Codex CLI на Mac не устанавливается. Пользователю не нужны Docker, Node.js, npm и отдельная установка runner. Адрес сайта задаётся при первом запуске; нужен работающий backend AI Router.

## Пользовательский сценарий

1. Установить AI Router из DMG и открыть приложение. При первом запуске появляется только конфигурация. После сохранения адреса сайта следующие запуски сразу открывают AI Router; настройки доступны через меню «AI Router → Доступ к Mac…». При переходе между сайтом и настройками остаётся одно видимое окно.
2. В окне «Доступ к Mac» сохранить HTTPS-адрес сайта, выбрать одну папку или расширенный доступ. Для обычного использования сайта оставить доступ выключенным.
3. Открыть AI Router, войти в аккаунт. В разделе «Исполнители» получить одноразовый код и вставить в настройки приложения. Это существующая привязка устройства; пароль аккаунта не передаётся локальному исполнителю.
4. Подключения к моделям назначаются серверному исполнителю. Не назначайте их Mac: он предоставляет только файлы и терминал.
5. Давать задачи в приложении или с сайта на другом устройстве. Mac должен быть включён, приложение запущено. При следующем запуске приложение само подключится с сохранённым доступом. Закрытие окна не завершает приложение; выход — через меню AI Router.

В меню **AI Router → Доступ к Mac** можно изменить режим. Сохранение изменений останавливает процессы; затем нажмите «Подключить Mac». **Остановить и отключить доступ** завершает исполнитель и его дочерние команды, выключает автоматическое подключение до нового явного выбора режима. Секрет устройства остаётся для повторного подключения; окончательная отмена привязки — кнопкой Disable на сайте.

## Права

- **Одна папка:** весь процесс исполнителя, включая дочерние shell-команды, запускается через macOS `sandbox-exec` с `deny default`. Разрешены выбранная папка, отдельный каталог данных исполнителя, его временные файлы, чтение системных инструментов и ресурсов приложения; сеть разрешена. Чтение других пользовательских файлов запрещено. Рабочие папки чатов остаются отдельными; путь выбранной папки передаётся агенту в контексте задачи. Это системный sandbox, не только `cwd`. `sandbox-exec` — устаревший механизм macOS; CI проверяет изоляцию и запуск Electron/Node на целевых версиях macOS. Если он недоступен, приложение не заменяет этот режим расширенным доступом.
- **Расширенный доступ:** исполнитель и команды работают с правами текущего пользователя. Для защищённых данных вручную добавьте AI Router в «Системные настройки → Конфиденциальность и безопасность → Полный доступ к диску». Это не root; интерактивное `sudo`, управление мышью, окнами и запись экрана не реализованы.
- Удалённая страница открывается без Node.js, preload и IPC-доступа к локальным настройкам. Разрешения меняются только в отдельном локальном окне. Внешние ссылки открываются в системном браузере. Секрет устройства и ключи хранятся в каталоге `executor` внутри Application Support AI Router с правами пользователя, конфигурация разрешений — отдельно.

Codex CLI в приложение не включён. Antigravity и Chromium для ChatGPT web не включены в эту сборку; системные Git, Python, компилятор и другие инструменты зависят от того, что установлено на Mac. Это не полный набор утилит Docker-образа.

## Исправление запуска 0.1.1

В режиме одной папки добавлено отдельное разрешение `file-map-executable` для системных библиотек, приложения и разрешённых рабочих каталогов, а также пути dyld Cryptex из правил Chromium. В 0.1.0 разрешалось чтение файлов, но отображение исполняемого кода не разрешалось. Это кандидат на исправление раннего падения dyld/libignition: конкретная запрещённая операция в присланном отчёте отсутствует; подтверждение на macOS 27.2 ещё необходимо. Режим доступа автоматически не расширяется. При аварии окно теперь показывает сигнал завершения.

Для расширенного доступа приложение можно вручную добавить кнопкой «+» в «Конфиденциальность и безопасность → Полный доступ к диску», выбрав `/Applications/AI Router.app`, затем перезапустить через Cmd+Q. Это разрешение не заменяет правила режима одной папки.

## Сборка

На Mac нужной архитектуры с Node.js 22+:

```bash
cd desktop
npm ci --include=dev
npm run dist
```

Артефакты появятся в `desktop/release`: DMG и ZIP. Для разработки: `npm run prepare:runtime`, затем `npm start`. Проверки: `npm test`; проверки системной изоляции и реального Electron runtime выполняются только на macOS.

Workflow `.github/workflows/desktop-macos.yml` собирает отдельные пакеты arm64 и x64 по ручному запуску или тегу `desktop-v*`, проверяет sandbox и сохраняет пакеты как Actions artifacts. Для пробной сборки 0.1.0 пакеты arm64 и x64 также упакованы на Linux в HFS+/UDIF DMG со встроенными macOS-версиями Codex CLI. Эти пакеты используют ad-hoc подписи без сертификата Developer ID и нотариального заверения Apple. Проверены хеши страниц кода, файловая система образов и обратное извлечение DMG; запуск приложения и изоляция папки на Mac пока не проверены. К DMG прилагаются START-HERE.txt, SHA256SUMS.txt и build-info.json с результатами проверок.

Для подписанной распространённой сборки в CI нужны `MAC_CERTIFICATE` (p12 в base64 или URL), `MAC_CERTIFICATE_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`. Без сертификата electron-builder создаёт неподписанную сборку: это артефакт разработки, прохождение Gatekeeper не подтверждено. Подписывание и notarization выполняются electron-builder при наличии настроенных данных Apple.

## Диагностика 0.1.3

Текст ошибок запуска исполнителя сохраняется в памяти и показывается под статусом подключения, включая ошибки enrollment, сети и sandbox-exec. При завершении процесса сообщение не теряется. Одноразовый код и распространённые поля секретов скрываются; лог ограничен последними 6000 символами. Это изменение диагностики, устранение причины завершения с кодом 1 на пользовательском Mac ещё не подтверждено.

## 0.1.4: чаты и доступ к Mac

Вместо полного runner поставляется только socket.io-client (около 3,6 МБ) и небольшой мост. Вход Codex в настройках Mac удалён. Кнопка установки веб-приложения скрыта внутри Electron; в браузере доступна. Добавлена собственная иконка PNG/ICNS.

Нужны обновлённые backend и серверный runner, а также HTTPS `PUBLIC_URL` backend. Мост соединяется исходящим WebSocket с `/mac`; открывать порты на Mac не нужно. Для обычных задач (`task`, standard) Codex получает MCP `ai_router_mac`, а OpenRouter/Cerebras выполняют `run_command` через мост. Режим chat остаётся без инструментов. Antigravity, ChatGPT web, CCC-Auto и общие подключения пока не используют Mac. Если подключён другой Mac того же пользователя, прежнее соединение отключается. При переключении устройств старые задачи не перенаправляются на новый компьютер.

Токен доступа создаётся отдельно для каждой серверной задачи и удаляется при её завершении или отмене. Отключение устройства на сайте разрывает мост. На Mac команды ограничены 120 секундами, четырьмя одновременными процессами и 24 000 символами вывода. Отключение моста останавливает дочерние команды. Модели и ключи провайдеров на Mac не скачиваются.

Проверки Linux подтверждают передачу команд, чтение/запись файлов, MCP handshake настоящим SDK, отмену и отзыв доступа. Проверка sandbox и реальный запуск macOS остаются в macOS workflow.

## Проверка обновлений 0.1.7

Приложение проверяет стабильные GitHub Releases при запуске и каждые четыре часа. При наличии новой версии предлагает скачать DMG для архитектуры текущего приложения. В меню AI Router доступна ручная проверка. Установка вручную: завершите приложение через Cmd+Q, откройте DMG и замените AI Router в папке «Программы».

Apple Developer для этого механизма не требуется. Сборки не подписаны Developer ID и не заверены Apple; запуск через Gatekeeper на реальном Mac не подтверждён. Первую версию с проверкой обновлений нужно установить вручную.

Для выпуска повысить версию package.json и package-lock.json, отправить коммит и тег `desktop-v<версия>`. Workflow проверяет приложение и публикует DMG для arm64 и x64 без секретов Apple. Ручной запуск workflow сохраняет артефакты без публикации. Токен GitHub в приложение не включается; репозиторий релизов публичный.

## Исправление упаковки 0.1.8

Исправлена ошибка `Cannot find module .../runner/node_modules/socket.io-client`: FileSet теперь копирует `runner` из родительской папки `runtime`, поскольку electron-builder исключает `node_modules` в корне FileSet. Хук `afterPack` загружает библиотеку и её зависимости из готового пакета для каждой архитектуры до подписания и создания архивов. Регрессионный тест использует настоящий копировщик electron-builder. В workflow включён `pipefail`, чтобы запись лога через `tee` не скрывала ошибки сборки и тестов.
